# iOSガラスタブの描画負荷・透明感の改善

対象は既存のシステム管理権限＋iOSモバイル幅のみ。ユーザーから本番版のタブ切替が重いとの報告があり、改善を依頼された。

## 変更

旧版は`.app-main`全体をhtml-to-imageで画像化し、DOMの変更ごとに更新していた。長いページでも全画面分のピクセルとCSSプロパティを処理する。今回、画面下部384 CSS pxだけを最大1.5倍で画像化し、範囲外の子孫は除外する。範囲外の外枠は計算済みの寸法で残して、本文の配置を保つ。画像化するスタイルはレイアウト・描画に必要な解決済みプロパティに限定し、数百個のCSS変数をノードごとに複写しない。

画面更新をまとめ、タッチ・スクロール・Next Linkの遷移待ちの間は新しい背景画像を作らない。キャッシュした範囲を外れたときはブラウザのCSS backdropを表示し、操作後に新しい背景へ戻す。シェーダーは元の04と同じ。`ops/glass/source.js`と`build-vendor.mjs`に変更と固定Git版からのビルド方法を保存した。

曇りを0.10→0.035、ぼかしを1.4→0.65に下げ、屈折を0.10→0.15へ調整。色ずれは12→9に抑制。CSSフォールバックも白い塗りを薄くする。選択レンズが離指直後に旧タブへ戻る処理を改め、Nextのpending/実際のルートへ追従させる。ブロックされた遷移では元へ戻る。

## 比較測定

同じ35カードの合成React画面、Chromium、390×844・DPR 3、CPU 4倍スロットリング。6回のタブ変更とスクロール1回。旧版は366d8c1の同じ部品。実機の通信・DBを含む画面遷移時間ではない。

| 指標 | 旧版 | 改善後 |
|---|---:|---:|
| 背景画像の1枚あたり画素数 | 6,383,520 | 336,960 |
| 50ms以上の処理の合計 | 5,188ms | 540ms |
| 最長フレーム間隔 | 897.6ms | 71.9ms |
| フレーム間隔p95 | 36ms | 18.1ms |

画像の画素数は94.7%減、長い処理の合計は89.6%減。新方式はスクロール先でも狭い画像を1枚作るため、この測定では旧6枚・新7枚。通常のマシン速度での往復タッチ確認ではp95 18.1ms・最大18.2ms。iPhone実機の改善率とは扱わない。

全523テスト、TypeScript、対象eslint、Chromium/WebKit 320/390pxで長押し反復・所有指追跡・役割と端末のゲート・未保存確認・再マウント・設定変更・作成ボタン間隔を確認。ブラウザの実タッチ入力で往復保持・離指時に1回だけ選択、キーボード、pendingとブロック、ベンダー失敗時の操作も確認した。最終本番相当buildを行ってから1回pushする。

測定は`.contingency/glass-performance.cjs`と`glass-performance-results.json`、操作確認は`test-glass-ui.cjs`/`test-glass-extra.cjs`。ビルドは`build-glass-performance-app.mjs`。DB・GAS・PC定期処理・ロール範囲に変更なし。実アカウント/iPhone実機は未確認。
