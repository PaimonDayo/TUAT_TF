# OB戦・システム限定の運営機能

## 対象と入口

オーナー依頼に基づく試用版。既存OB戦プログラムの「補助員」を、実効システム管理権限がある人だけ「運営」へ変更する。「出場・補助」「組み分け」「試技記録」は既存の共通タブ・入力・全画面フォームを使う。システム権限だけの人にも運営機能を提供するが、従来のエントリー／補助員編集はOB戦担当権限を引き続き必要とする。一般部員プレビュー、一般部員、OB戦担当だけの人には新しい運営データを渡さない。

## 実装

- 現役の補助員表へOB・OGの競技予定を統合。OB・OGは紫の氏名・出場印・薄い行背景と区分表記で識別し、補助員候補／本人照合には含めない。
- 氏名は1行省略。出場は●、同時刻の別種目は斜線、補助担当は■＋略称、当日確認は△。タップ／キーボードで詳細を確認。空欄を担当可能とは判定しない。
- 全員／現役／OB・OGと終日／午前／午後の絞り込み、氏名検索、固定氏名・見出し、横スクロール、CSV出力。
- 種目別（男女別）の組・レーン／試技順を編集。仮配置は未配置者だけが対象。既存の手動配置・試技を保持する。同じ組の番号重複を保存時に拒否する。
- トラックは1記録、距離種目は最大6試技、高跳びは高さと○×−を1試技ずつ最大30件。対応種目だけ風速を入力でき、0・負数も保存。DNS／DNF／DQと速報／確認済みを区別。ベストを表示する。正式順位や同記録の順位決定は行わない。
- 種目単位の期待revision付きRPCで原子的に保存。別端末の更新は上書き拒否。保存失敗時は入力を保持し、未保存で閉じると共通確認を表示。
- 新規参加者は追加し、エントリーを取り消した人の入力済み記録は自動削除しない。確認済みにするには取消者を欠場にする必要がある。競技回答・資格記録・補助員担当を試技記録で上書きしない。
- 新規2表はシステム限定SELECT、本人JWTを使うRPCのみ更新。匿名／一般部員／OB担当のみの更新・直接書込みを拒否。変更者と変更前後を監査表に保持する。PC→予備クラウドのコピーと停止中の書戻しにも2表を追加。

## 再利用の基準

1. `MeetMark` は記録の値、`MeetEvent` は組・試技を扱うオブジェクト。React・DB・大会名へ依存させない。表示文字列を状態判定へ使わず、型で定義した状態を使う。
2. 大会固有の名簿・種目・開始時刻は `ObMeetRoster` と `obEventRule` のアダプターへ置く。他大会はルールと参加者の変換を追加する。継承階層を増やさず、ルールの合成で再利用する。
3. UIは共通部品を組み合わせる。権限はサーバー画面・Action・DBの3層で確認し、UIの非表示だけを保護とみなさない。
4. DBアクセス型は専用 `ob-operations-db.ts`、初期取得は `lib/queries/`、変更はServer Actionへ分離する。ドメイン側とSQL側の境界チェックをテストする。
5. 保存成功前に成功表示しない。revision競合、入力不正、取得失敗を空データや成功へ変換しない。新しい機能でも既存データを黙って消さない。
