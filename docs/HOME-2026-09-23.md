# ホーム表示・取得処理・文書の整理

## 変更

ホームの各欄が別々に出現し、週間集計の後挿入や空の欄の消失で予定・投稿が動いていた。本文の6系統の取得を `Promise.all` で同時に開始し、一つの `Suspense` でまとめて表示する。見出しは先に表示し、ルートのloadingと本文で同じ `HomeSkeleton` を使う。端末判定後に出るホーム画面追加案内は末尾へ移した。

本文は最も遅いDB取得を待つ。一方、ホームの初期取得から外部スプレッドシート待ちを外した。本日の中長距離メニューは予定を展開したときだけ取得する。今後の予定のコンパクトカードや短距離だけの予定ではCSVを取得しない。取得中は詳細内のスケルトン、失敗時は再読み込みボタンを表示し、既存のDBメニューがあれば保持する。

ホームと予定一覧は同じメニューQuery定義を使う。ユーザーID・対象月が同じ要求はまとめ、60秒以内の再表示とwindow focusでは再取得しない。通信のキャンセル信号を引き継ぎ、失敗の自動再試行はしない。予定一覧も含め、後から届いたメニューをカードのローカル状態へ反映する（従来は初回のpropsしか反映されなかった）。

週間集計は記録本文・著者・項目定義を取らず、距離の5列だけで合計と件数を計算する。本人・過去7日・未来日除外・空記録除外・距離の計算方法は維持。中長距離以外は集計自体を呼ばない。集計エラーを0として表示しない。

27大戦のプログラムは9/23を9/22の上に表示する。日付グループを降順にし、各日のトラック/フィールドと開始時刻順は維持。ホームの導線も同じプログラム画面に遷移する。記録・結果・同期データは変更しない。

## 文書整理

古い引き継ぎ・公開前メモ・適用済みの更新指示・初回PC切替前計画の4文書を削除した。詳細と残した文書の用途は [文書案内](README.md)。README、Claudeの入口、AGENTSの現行索引、UI規約、通知設計の報告先、PC運用の現在/過去の区別を更新した。監査・インシデント・復旧手順を維持し、古い本文はGit履歴に残る。
