# ガラスタブの透け方の統一（2026-09-30）

## 症状と原因

「透けるところとそうでないところがあり、統一感がない」という指摘を受けて確認。
WebGL が描画できる状態と、スクロールで背景の切り取り範囲を外れた状態・読み込み待ち・描画失敗時で、別々のガラス素材へ切り替わっていた。

- WebGL のぼかしは 0.65px、白い膜は 3.5%。
- フォールバックでは外側の 9px のぼかしに、vendor 内の 9px のぼかし・白いグラデーションが重なる。
- 縁と陰影も WebGL の有効・無効で別のものに切り替わる。
- 選択中の楕円にも、上部と中央で濃さの違う塗りがある。

実 React UI の Chromium / WebKit 両方で、GL context loss を起こして、この描画状態の差を確認した。

## 修正

外側の CSS にガラスの土台を一本化。ぼかし 0.65px / 彩度 135% / 均一な白 3.5% / 共通の縁と陰影を、背景の取得状態にかかわらず使う。
vendor の shadow DOM の glass / border を parts として公開し、アプリ側では二重になる装飾を非表示にする。固定版の屈折シェーダーは変更しない。
選択中の楕円は均一な白 8% にし、輪郭の反射と長押し変形は維持する。
vendor URL は v3。system ロールと iOS の判定、一般部員プレビュー、画面遷移、背景の 384px 制限・最大 1.5 倍・操作中の取得延期は変更しない。

背景そのものの色・カードの有無による見え方や、フォールバック時に屈折がなくなる差は残る。すべての背景を同じ色にする変更ではない。

## 検証

- tsc / 対象 eslint / 全 523 テスト成功。
- Chromium / WebKit の 320px・390px：全タブ、長押し 3 往復、指の識別、フォームの重なり、ロール切替、再マウント、低減設定、Android / PC の対象外判定を確認。
- 実ブラウザの touch 入力・離指で 1 回だけ遷移・キーボード・pending / キャンセル・vendor 読込失敗のフォールバックを確認。
- 青・緑の帯状背景で GL 有効時と context loss 後を比較。両エンジンで共通素材の computed style が一致し、vendor の二重の膜は非表示。画像も確認。
- CPU 4 倍の合成比較：変更前後とも 7 回の取得、1 回 585×576（336,960 画素）、style 読取 1,002 回。フレーム p95 は両方 16.8ms。long task 合計 499→541ms、最大フレーム 66.7→83.5ms。この単発比較を速度向上とは扱わず、取得量が増えていないことを確認。
- 合成設定の隔離本番ビルド（Next 16.3.6 / TypeScript 込み）成功。DB / GAS / PC 定期処理の変更は不要。

検証スクリプトと画像は `.contingency/test-glass-consistency.cjs`、`test-glass-ui.cjs`、`test-glass-extra.cjs`、`glass-consistency-performance.cjs` および同ディレクトリの結果画像・JSON。iPhone 実機は未確認。
