# PC・タブレットの入力フォームを全画面へ統一

2026-10-08 / 担当: Codex。所有者の今回指示は、スマホで全画面になるノート・投稿などの入力フォームについて、PC・タブレットでも無駄な横余白を設けず全幅へ表示すること。直前の本番公開指示を継続し、この修正だけを検証後にまとめて本番公開する。

## 受入条件と再現

- 作成/編集の入口から全画面フォームを開き、スマホ・タブレット・PCの各幅でフォーム外枠が画面の左右端に一致する。本文・固定保存操作も通常の16pxの入力余白以外の幅制限を持たない。
- 既存のヘッダー、戻る、未保存変更確認、スクロール、フッター、キーボード追従、入れ子の選択操作、権限と保存内容を保持する。
- 保存・破棄・失敗復旧の既存ロジックは変更しない。作成メニューなどの選択シートと確認ダイアログへ全画面化を広げない。

本番の認証済みノート一覧→作成メニュー→フォルダの空フォームで再現した。1280pxの画面に対してフォーム幅672px/左304pxだった。共通FullScreenContentのmax-w-mdとmd:max-w-2xlが原因。FormModalにもwide指定で別の上限を作る経路があり、全フォームへ統一するため撤去する。DB・データ・本番PCの依存やプロセスは変更しない。既存の元checkoutの別作業差分と直前の本番反映記録を保全し、最新origin/masterから専用作業ブランチで進める。Next 16同梱CSSガイドを確認した。

検証・commit・本番反映結果は終了時に追記する。

## 修正と検証

FullScreenContentの本文と背面の最大幅・中央寄せを除去し、全幅表示へ統一した。FormModalのwide分岐と4呼出箇所のwide指定を撤去した。既存の16px本文/フッター余白、固定ヘッダー/保存ボタン、フォーカス・キーボード追従・未保存確認コードは保持する。

専用worktreeの依存35件一致、TypeScript、対象6ファイルeslint、全Vitest122ファイル/1098件、差分空白検査が成功。実NoteEditorと共通FormModalを使うブラウザ検証用の私有fixtureで、390/600/768/1024/1440/1920pxの各幅で左0px・画面と同じ幅・横はみ出しなしを測定し、1024pxのフォームを画像でも確認した。幅/高さ変更後の入力保持・固定フッターの画面内表示、戻る→未保存確認→編集継続→入力保持を確認した。fixtureはDBとルーティングが合成のため本番保存・実機キーボード試験とは扱わない。確認ダイアログと選択シートの既存幅は保持した。検証fixtureは公開Gitへ含めない。

公開直前のnpm run buildが成功（Next 16.3.6、型検査・69静的ページ生成完了）。最新origin/masterは引き続き直前の公開commit `3dc1714`。今回のフォーム修正と今回/前回の反映記録9ファイルだけをまとめ、masterへfast-forwardして1回pushする。DB migrationは不要。
