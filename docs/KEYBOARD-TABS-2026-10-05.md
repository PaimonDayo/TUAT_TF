## 受入条件と調査

- 部員が通常画面の入力欄を開き、キーボードを閉じて、同じ入力欄を再度開いても、下部タブがキーボード上へせり上がって入力を妨げない。
- 入力からフォーカスが外れても、キーボードの閉じるアニメーション中は下部タブを出さず、通常の表示高さが戻った後に下端へ戻す。キーボードだけを閉じ、入力欄のフォーカスが残る場合もタブを復帰させる。
- 通常スクロール時のブラウザバー追従、キーボードを閉じた後の画面回転、拡大操作、全画面入力の可視領域追従と閉じて再度開く操作を保持する。入力内容・保存・データ・権限は変更しない。
- 実機を使わない検証はキーボードイベントとサイズの合成再現として記録し、iOS PWA/Androidの実機確認へ読み替えない。

修正前コードはタブの `top` を常に `visualViewport.offsetTop + height - offsetHeight` へ変更し、非表示条件は「入力focusがあり、`innerHeight - visualViewport.height > 150`」のみ。アプリのviewportには `interactiveWidget: "resizes-content"` が既に設定されている。[Chrome公式の説明](https://developer.chrome.com/blog/viewport-resize-behavior)ではこの設定でvisual/layout両viewportが縮む。その条件では2つの高さの差が0でもキーボードが開いているため、既存の非表示判定が成立しない。focusが先に外れて高さの復帰が遅れる条件も、キーボード上の位置でタブが再表示される。

上記を合成してから修正する。所有者端末のOS・ブラウザ・実viewport値は未取得であり、報告された実機障害の原因がこの条件だけだとは断定しない。Next 16同梱のClient ComponentsとgenerateViewportガイドを確認した。新しい設定・UI・独自キャッシュを追加せず、既存のviewport同期だけを修正する。
