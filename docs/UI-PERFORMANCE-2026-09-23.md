# 現行アプリの表示・通信改善（2026-09-23）

同日追加: ホーム本文の表示単位と取得処理は、この後の [ホーム改善・文書整理](HOME-2026-09-23.md) で更新した。ホームは見出し先行・本文一括表示、メニューCSVは予定展開時の取得になっている。以下はそれ以前のタブ配置・通信改善の検証記録。

対象はルートの現行Next.jsアプリ。新アプリの実装、DB、認証設定、cron、課金プランは変更していない。

## 変更

- 下部ナビをbody直下に置いたまま、visualViewportのresize/scroll、画面復帰、入力フォーカス変更に追従させる。1フレーム1回に集約し、Reactの再描画や通信は発生させない。キーボード表示中は下部ナビを隠し、閉じた後に再配置。背景のぼかしを外して描画負荷を軽減。同じタブの再タップは先頭へ移動し、再遷移しない。
- 全画面フォームのviewport同期をDOMが実際にマウントされた時点から開始。以前は閉じたDialog.Portalのrefがnullの時点でeffectが終了し、後から開いても追従しない場合があった。位置調整にtransformを使わず、入退場アニメーションと競合させない。
- 予定のSSR直後の`/api/schedule-page`再取得を停止。シートメニューは60秒間再利用し、画面フォーカスだけでは取り直さない。明示的な編集・引き下げ更新は維持。
- 引き下げ更新ではサーバーから再取得する予定・ノート・タイムライン・グラフのクライアント取得を重ねない。タイムラインは新しいサーバーデータをキャッシュに反映し、同じサーバースナップショットに戻る場合は追加読み込み済みページを維持する。
- 通知の未読確認（2分）とバージョン確認（5分）は、短時間の画面復帰でも間隔を守る。非表示・オフライン中は送信せず、重複実行を防止、25秒で中断、アンマウント後の応答を破棄する。
- FABから開く各フォームを動的読み込みに分け、フォームを待つ間はスケルトンを表示。予定・ノートの見出しをデータ取得から分離。マイページのプロフィールはグラフを待たずに表示し、グラフ非表示の部員では専用の記録取得を省略。
- スケルトンの見出しにsafe-areaとPC表示時の高さを反映。動きを減らす設定を尊重。タブ遷移中の読み込み表示を追加。
- ルートのTypeScript/ESLintの対象から独立パッケージ`tuat-tf-next/`を除外。新アプリからルートの型を誤って参照する検証混入を防止。

## 検証

- Vitest: 今回追加した8件で、復帰連打時の要求数、非表示・オフライン、同時要求の抑制、タイムアウト、遅延応答破棄、viewportサイズ変更、キーボード開閉、フォーム再表示、ピンチズームを確認。
- TypeScript・対象ESLint・PC本番設定によるNext.js production build成功。
- ローカル合成UIをブラウザで390px/320px表示。下部ナビの下端＝可視領域下端、横はみ出しなし。フォーム開閉を反復し、改行入力、閉じた後のナビ復帰、見出し・スケルトン・固定フッターの表示を確認。一時ルートは削除済み。
- 認証済み本番操作の速度・通信量の変更前後比較、iOS Safari/PWA実機での症状再発確認は未実施。合成画面での成功を実機不具合の完全解消とは扱わない。

## 負荷と残る確認

Vercel使用量を既存CLIで読み取り確認した。今回の削減は不要な取得をなくすもので、月間制限を保証するものではない。料金・使用率の値はチーム単位なので公開リポジトリには保存しない。

再確認は、予定初回表示時の`/api/schedule-page`が0件であること、1分以内の予定再訪でメニューを取り直さないこと、アプリ復帰を連打しても未読確認の2分間隔が崩れないこと、引き下げ更新で表示が最新になり同じデータ取得が重複しないことを見る。

主要タブの通常の部分prefetchは維持。追加の全画面prefetch、`cacheComponents`、`experimental.staleTimes`は導入していない。参考: [Next.jsのprefetch](https://nextjs.org/docs/app/guides/prefetching)、[Vercel Functionsの使用量](https://vercel.com/docs/functions/usage-and-pricing)。
