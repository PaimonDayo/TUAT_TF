# スプレッドシート連携の表示項目一覧

## 開始・受入条件

- 2026-10-15、Codex担当。所有者依頼は「誰が何の項目を表示にしているかを、管理者の設定からシステム管理者が確認する」。対象はスプレッドシート連携の現在設定。
- 現状: 設定のシステム管理にはサービス状態等があるが、部員ごとの連携・表示項目一覧がないことをコードで確認。認証済みの実画面操作は未再現。
- 入口は設定 → システム管理 → スプレッドシート連携。システム管理権限をサーバーで確認し、一般部員・部員管理権限のみ・一般部員プレビューからは開けないこと。
- 氏名、学年、連携シート、入力方法、入力フォームとタイムラインの表示項目を現在の保存値から表示する。名前検索と学年別表示を備える。連携なし・未確認・表示選択なし・旧形式の標準表示を区別し、部員を取得上限や未知の学年で欠落させない。
- 過去の設定や練習記録本文・メールは一覧へ送らない。本人の設定、記録、連携動作、既存RLSは保持する。取得失敗は空一覧にせず、再試行できること。
- 既存作業コピーの未コミット変更を保持し、fetch後の最新origin/masterから独立作業。別の全体改善や本番PC・DB・GAS設定は対象外。

## 終了・検証

- 設定 → システム管理 → スプレッドシート連携（`/admin/sheets`）を追加。氏名・学年・ブロック・卒業状態、連携シート、入力方法、フォーム項目、タイムライン表示項目を確認できる。名前・シート名の検索と学年別表示を備える。
- UI入口・ページ・取得処理で既存の `manageSystem` を使用。部員管理のみ・権限なし・一般部員プレビューでは一覧を取得しない。本人IDの検証は既存の `getCurrentProfile()` に委譲する。
- `profiles.record_fields` の現在値だけを使用。連携停止時に保持された設定と未確認を区別し、固定項目には「標準」を添える。旧形式の非表示・表示名も保持し、旧設定を未設定と誤案内しない。過去の設定はクライアントへ渡さず、連携方法だけを渡す。記録本文・メールは取得しない。
- RLS付き取得をID順・500件ずつ実施し、途中の失敗と不明応答は例外にする。既存の共通エラー画面で再試行できる。シート・DBの更新処理とmigrationは追加していない。
- Node.js 24.19.0 とロックファイル一致の35依存で `check:environment`、TypeScript、対象eslint、Vitest全149ファイル・1,273テストが成功。権限拒否、複数ロール、現在設定と過去設定の分離、全件取得・途中取得失敗、入力だけの項目・非表示項目・表示項目・旧形式・未知の学年・卒業・連携停止を検証した。
- 実コンポーネントを合成データだけでブラウザ表示し、シート名検索、該当なし、検索解除を確認。390px幅で長い項目名の折返しと横はみ出しなし（表示幅・内容幅とも390px）を確認した。認証済み本番画面、iOS PWA・Androidの実機操作は未確認。
- 合成の接続値のみを使った `next build --webpack` が成功。検証では共有の本番依存・本番サービス・実DB・実シートを変更していない。今回だけの検証サーバーは終了した。
