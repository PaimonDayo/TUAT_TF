## 1. 高：投票取消に失敗しても、画面だけ取消済みになる

- 根拠: src/components/features/PollView.tsx:156。removeVotes の boolean を確認せず選択状態・票数を更新している。TweetPoll.tsx / NotePoll.tsx は失敗時 false を返す。
- 影響: 通信失敗でも成功したように見え、再読込みで投票が戻る。単一選択の切替でも取消失敗を確認せず次の登録へ進む。登録・選択肢追加の失敗も利用者への通知がない。
- 改善: 成否を確認してから表示を更新し、失敗時は共通トーストで再試行を案内する。単一選択の切替は途中失敗時の状態も照合する。
- 確認: 取消APIを失敗させ、元の選択・票数を保持して失敗を通知すること。取消成功後の新規投票失敗も確認する。

## 2. 高：未保存の入力を閉じる操作が画面ごとに異なる

- 根拠: MyPageActions.tsx:42、GoalEditor.tsx:70、VenueManager.tsx:140/152、RecordFieldsSetting.tsx:137 は直接閉じる。一方、CompetitionGoalsView.tsx の requestClose と FAB.tsx の記録・つぶやきには UnsavedChangesDialog がある。
- 影響: 同じ「戻る」でも確認が出る画面と入力が消える画面がある。自由目標・記録フォーム設定は再び開くと元の値へ戻す。
- 改善: 変更なしは即閉じる、変更ありは保存・破棄・編集継続、保存中は閉じない、を共通化する。
- 確認: 各フォームで変更後に戻る／Escape。確認から編集継続して入力が残ること。保存失敗後にも残ること。

## 3. 中：キャッシュの更新失敗が利用者に伝わらない

- 根拠: ScheduleCachedView.tsx:26 と NotesCachedView.tsx:12 は useQuery の data だけを使用。予定の外部メニュー取得もエラー状態を表示へ渡していない。QueryProvider に共通エラー通知はない。
- 影響: 再取得に失敗したとき、古い内容が最新かどうか判断できない。初回ページ全体のエラーとは別の問題。
- 改善: 表示済みデータを残したまま「更新できませんでした」と再試行ボタンを表示する。更新中・更新失敗・0件を分ける。
- 確認: 初回成功後に再取得だけ失敗させ、既存表示を維持しつつ再試行できること。
