# 大会結果入力とタイムラインの下部ガラス（2026-10-01）

## 大会・記録会の入力

- 風速の符号を「＋ 追い風」「− 向かい風」のボタンで選択し、数字キーボードでは大きさだけを入力する。既存の負数は向かい風で開き、保存する風速は従来と同じ符号付き数値。空欄はnull、0は0として保存する。PC入力・貼り付けの正負符号、全角数字、Unicodeのマイナスも受け取る。
- 新規作成時の大会入力を「大会から選ぶ」で開始する。既存の自由入力記録の編集は、その大会名と入力方式を保つ。
- 複数日の大会を選ぶチップは、選択状態だけで文字の太さが変わっていた。実ReactフォームのChrome/WebKitで、選択変更後に隣のチップが5.375px動くことを再現。`text-body`が`cn`内のクラス統合で選択色と競合し、非選択側だけ400の太さが残るため、明示した14pxと固定の太さへ統一する。文字間隔も固定し、44px以上の操作領域を確保する。

## タイムライン切替の調査

実TimelineViewとBottomNavを組み合わせた合成画面で調査。表示が落ち着いた後のガラス材質はページ間で共通で、背景画像の位置差も0pxだった。タイムラインは白いカードが広いため、その部分が透けると白く見える。

一方、ページが切り替わっても前ページの画像キャッシュを表示し続ける経路を再現した。320pxのChromeで切替後約0.31〜0.56秒、古い画像がWebGLの中に残っていた。その後にタイムラインの画像へ差し替わるため、透け方が遅れて変わって見える。

ページのpathnameが変わった時点で古い背景キャッシュを無効化し、新しい画像が用意されるまでは既存のCSSによる現在の背景表示を使う。GPU・ガラス面は作り直さず、通常のメニュー開閉ではキャッシュを保つ。
