# サーバーPCの消費電力を下げる

最終更新: 2026-09-19 / Claude Opus 5

このPC（GALLERIA XA7R-R36T / Ryzen 7 5700X / RTX 3060 Ti / 32GB）は本番のDB・Authを動かしている。
**スリープと休止は入れられない**（寝た時点で部員がアプリを開けなくなる）。
つけっぱなしのまま減らせるところだけを触る。

## 1. 電源設定（実施済み 2026-09-19）

```powershell
powershell -NoProfile -File ops/laptop/power-saving.ps1 status
powershell -NoProfile -File ops/laptop/power-saving.ps1 apply -DisplayOffMinutes 5 -MaxCpuPercent 100
powershell -NoProfile -File ops/laptop/power-saving.ps1 restore
```

| 設定 | 前 | 後 | ねらい |
|---|---|---|---|
| ディスプレイの電源を切るまで | 120分 | **5分** | 4Kモニタは20〜40W。誰も見ていない時間がいちばん長い |
| スリープするまで | 120分 | **しない** | 省電力ではなく取りこぼし防止。下の注意を参照 |
| 休止状態にするまで | 121分 | **しない** | 同上 |
| 最大のプロセッサの状態 | 100% | 100%（**変更なし**） | オーナー判断でCPUは触らない（2026-09-19） |
| PCI Expressの省電力 | 中 | **最大** | 使っていないPCIeリンクを深く寝かせる |

変更前の値は `.contingency/power-saving-before.json` に控えてある。`restore` で元に戻る（動作確認済み）。

**スリープを「しない」にした理由**: 今までスリープしていなかったのは、常駐タスク（`backend-task.ps1`）が
`SetThreadExecutionState` で抑止していたから。つまり**そのプロセスが落ちた隙に寝てしまう**状態だった。
実際には寝ていないので電力は増えない。設定としても「しない」に固定して、止まる経路をひとつ減らした。

**CPUをもっと下げたくなったら**: `-MaxCpuPercent 99` でターボ（最大4.6GHz）だけ止まり、基本クロック3.4GHzは出る。
DBの中継には十分で、ここがいちばん電力が減る。`-MaxCpuPercent 60` なら約2GHz上限でさらに下がる。
ゲームなど他の用途の速度も落ちるため、今は入れていない。

## 2. いま何が電気を使っているか（2026-09-19 実測）

- **GPU**: アイドル13.06W（コア210MHz / メモリ405MHz）。すでに十分低い。画面を消すともう少し下がる。
  Ryzen 7 5700X に内蔵グラフィックはないので、RTX 3060 Ti を外すことはできない。
- **DBの置き場所**: WSLの仮想ディスクが外付けHDD（E:）にあり、Postgresが常に書いているのでHDDは**止まらない**（常時5〜8W程度）。
  稼働中にHDDを抜くとWSLごと停止する。
- **コンテナ**: 11個すべてhealthy。アイドルでも `supabase-db` 13.6% / `supabase-auth` 8.7%（CPU1コア比）。
  中身は下の死活確認。
- **オーナー自身のアプリ**: 起動からの累積CPU時間は OneDrive同期 6,585秒 / Discord 約4,100秒 / エクスプローラー 5,586秒。
  席を離れるときにDiscordを閉じるだけでも、CPUとGPUの張り付きが減る。

## 3. まだ手を付けていない案

**死活確認の間隔**（効果あり・要停止判断）: 11コンテナ中8つが**5秒ごと**に死活確認している（残りは10秒・30秒）。
1秒あたり2回近くプロセスが起動し続け、CPUが休みきれない。30秒へ延ばせば回数は1/6になる。
ただしコンテナの作り直しが必要で、**その間APIが一時的に止まる**。実施するならオーナーの合意と、
composeは必ず4ファイルを揃えて実行する（2026-09-10に1ファイルだけで実行して12分落とした事故がある）:

```bash
docker compose -f docker-compose.yml -f compose.local.yml -f compose.rehearsal.yml -f compose.auth.json up -d
```

**バックアップの間隔**: 15分ごとのダンプ＋暗号化＋R2送信は、数秒とはいえCPUとHDDを動かす。
ただしこれはデータを失わないための仕組みなので、電力のために延ばさない。

**WSLのメモリ上限**: 既定で物理メモリの50%（約15.6GB）を割り当てている。`.wslconfig` で絞れるが、
電力への影響はほとんどない。
